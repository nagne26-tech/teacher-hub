# 티처 허브

## 공용 자료실과 교사 승인

기존 개인 작업실은 그대로 두고 공용 자료실을 추가했습니다.
- `/#/classroom`: 학생과 교사가 로그인 없이 쓰는 수업 앱
- `/#/teachers`: 로그인 후 관리자가 승인한 교사만 업무 앱 조회
- `/#/manage`: 교사 가입·로그인, 관리자 승인·취소 및 공용 앱 등록·수정·삭제

공용 앱·교사 계정·승인·세션은 Python 표준 라이브러리와 SQLite 서버에 저장합니다.
개인 작업실에 등록한 링크는 자동 공유되지 않습니다. 관리자가 공유할 링크를 별도로 등록하세요.

### 처음 실행

프로젝트 폴더에서 실행합니다. Python 3.10 이상이 필요합니다.

```sh
pnpm build
python3 server/server.py --create-admin
python3 server/server.py
```

관리자 생성 명령은 이메일·이름·비밀번호를 터미널에서 입력받습니다. 기본 계정이나 기본 비밀번호는 없습니다.
`http://127.0.0.1:8787/#/manage`에서 로그인하세요. 교사는 가입 요청 후 관리자의 실제 신원 확인과 승인을 기다립니다.
비밀번호는 12~128자이며 PBKDF2-SHA256(600,000회, 개별 salt)으로 저장합니다. 세션은 HttpOnly·SameSite 쿠키로 8시간 유지되며 서버에는 토큰 해시만 저장합니다.
승인 상태와 관리자 권한은 API 요청마다 확인합니다. 승인 취소는 기존 세션에도 적용됩니다.

### 개발 및 배포

Vite 개발 시 서버를 `HUB_PUBLIC_ORIGIN=http://127.0.0.1:5173 python3 server/server.py`로 실행하고, 별도 터미널에서 `pnpm dev`를 실행하세요. Vite의 `/api` 요청을 8787 포트로 전달합니다. 실제 접속 주소와 origin 설정은 정확히 일치해야 합니다.

공개 운영에는 정적 파일만 올리면 안 됩니다. Python API와 SQLite를 함께 실행할 서버·영구 저장소 및 HTTPS 리버스 프록시가 필요합니다. `HUB_PUBLIC_ORIGIN=https://실제도메인`으로 지정하면 Secure 쿠키를 사용합니다. 필요하면 `--host`와 `--port`를 지정하세요.
DB 기본 경로는 `server/data/hub.sqlite3`이고 `HUB_DB`로 변경할 수 있습니다. DB에는 계정 정보가 있으므로 소스와 별도로 안전하게 백업하세요. 현재 공개 배포는 하지 않았습니다.

중요: 교사 자료실은 외부 앱 링크를 승인된 교사에게만 전달합니다. 외부 앱 주소를 직접 방문하는 것까지 이 허브가 막아주지는 않습니다. 민감한 행정 앱은 해당 앱에서도 인증과 권한 검사가 필요합니다.
이메일 인증·메일 발송·자동 비밀번호 재설정은 포함하지 않습니다. 교사 여부는 관리자가 직접 확인합니다. 서버의 기본 개발 HTTP 호스트 대신 공개 운영 시에는 적절한 운영 호스팅을 구성하세요.

서버 권한 검증: `python3 -m unittest discover -s server -p "test_*.py" -v`


## 실행
Node.js와 pnpm 환경에서 `pnpm install` 후 `pnpm dev`로 실행합니다.
`pnpm build`는 배포 가능한 정적 파일을 `dist/`에 만듭니다.
`pnpm test`로 계산·백업·타이머 검사를 실행합니다.

## PDF 글자 수
허브 홈 또는 내 앱의 PDF 글자 수 세기에서 실행합니다.
PDF.js와 worker, CMap, 표준 폰트 및 WASM을 앱과 함께 제공합니다.
선택한 파일은 ArrayBuffer로 읽어 브라우저 worker에서 분석합니다.
파일·파일명·추출 텍스트·결과는 서버로 전송하거나 localStorage,
IndexedDB 등 영구 저장소에 기록하지 않습니다. 파일과 결과는 화면 이동,
새로고침 또는 지우기로 폐기합니다. 허브 앱 목록·즐겨찾기만 별도로
localStorage에 보존합니다. PDF 분석에는 외부 CDN/API 및 분석 추적 코드를 사용하지 않습니다. 공용 자료실은 동일 출처의 `/api` 서버를 이용합니다.
앱 코드 및 PDF 지원 자원 로드는 같은 출처의 정적 GET 요청입니다.
CSP로 외부 출처 연결과 폼 제출을 차단합니다.

공백 포함/제외 및 페이지별 글자 수를 제공합니다. NFC 정규화 후
Intl.Segmenter의 grapheme 단위로 계산하고 줄바꿈을 제외합니다.
공백 제외는 모든 유니코드 공백을 제외합니다. OCR은 지원하지 않으며
텍스트가 없는 페이지는 별도로 안내합니다. PDF 저장 방식에 따라
띄어쓰기·숨겨진 텍스트·머리말과 꼬리말이 결과에 영향을 줍니다.

검증: 테스트 9개, TypeScript 검사 및 Vite 빌드 통과.
브라우저에서 `Hello PDF 123!` PDF가 공백 포함 14자, 제외 12자로
분석되는 것과 결과 지우기·허브 연결을 확인했습니다.

## 개인정보 점검·비식별화

홈 / 개인 작업실의 **개인정보 점검·비식별화** 카드에서 엽니다.
경로: `/#/apps/privacy-guard`. 개인정보 처리에는 API 서버가 필요하지 않습니다.
기존 허브 서버는 앱 정적 자원을 제공하는 용도로만 사용합니다.
외부 CDN·AI·분석 서비스·영구 저장소 없이 탭 메모리에서 처리합니다.
PDF/XLSX/XLS 1개, 30MB, PDF 100페이지, Excel 20만 셀까지 지원합니다.

- 주민번호·전화번호·이메일은 패턴으로, 이름·학번은 라벨/엑셀 열 머리글로 후보를 찾습니다.
- 추가 검색 문구, 후보 선택/해제, PDF 페이지별 직접 영역 지정, 엑셀 셀 전체 가리기를 제공합니다.
- PDF는 페이지를 렌더링하고 가림 영역을 검정 픽셀로 덮은 뒤 새 PDF로 만듭니다. 원본 텍스트·메타데이터·첨부·주석 객체는 복사하지 않습니다. 텍스트 검색은 사라집니다.
- XLS/XLSX는 모든 시트의 셀을 점검하며, 표시 값을 새 XLSX의 텍스트 셀로 옮깁니다. 수식·서식·메모·링크·그림·매크로·원래 시트명·문서 속성은 복사하지 않습니다. 숨김 셀은 출력에서 보입니다.
- 암호/손상 파일은 거절합니다. 캐시 결과 없는 수식은 값으로 변환한 파일을 요구합니다.
- OCR은 제공하지 않습니다. 스캔·이미지·회전·세로쓰기·주소·문맥 없는 이름/학번은 직접 확인하고 가려야 합니다. 탐지 0건이 개인정보 없음이나 완전한 익명화를 뜻하지 않습니다.
- 지우기·새로고침·화면 이동 시 앱이 파일 참조를 해제합니다. 원본 파일과 이미 내려받은 파일은 사용자가 관리합니다.

검증: 자동 테스트 총 14개 통과, TypeScript/Vite 빌드 성공.
브라우저 가상 XLSX에서 이름·학번·전화번호 3개 탐지 후 다운로드하고,
출력을 다시 읽어 식별정보 삭제 및 일반 내용 보존을 확인했습니다.
가상 PDF의 전화번호·주민번호 2개 탐지 후 다운로드하고,
출력 PDF에 원문 텍스트·주석·첨부가 없음을 확인했습니다.
실제 학생 자료는 검증에 사용하지 않았습니다. 공유 전 결과 전체를 직접 확인하세요.
